## Overview

P<sup>2</sup>DNet is a point-supervised panoramic object detection framework that converts sparse point annotations on equirectangular projection (ERP) images into pseudo bounding fields of view (pseudo-BFoVs). The generated pseudo labels can then be used to train downstream panoramic object detectors, reducing the annotation cost associated with manual BFoV labeling.

The pseudo-label generator follows a coarse-to-fine two-stage pipeline:

1. **Coarse FoV Proposal Generation (CFG)** generates multi-scale spherical proposals around each point, extracts distortion-aware spherical RoI features, scores proposals with multiple instance learning (MIL), and aggregates the top-ranked proposals on the sphere.
2. **Fine FoV Proposal Refinement (FFR)** progressively refines the coarse BFoV through spherical jittering, multi-scale proposal expansion, negative proposal generation, MIL scoring, and spherical weighted aggregation.

## Highlights

- Point-supervised pseudo-BFoV generation for ERP panoramic images.
- Multi-scale BFoV proposal initialization on the sphere.
- Shared-weight original and scale-rotated branches in the coarse stage.
- Distortion-aware spherical RoI feature extraction through tangent-plane sampling.
- Top-\(k\) spherical weighted proposal aggregation.
- Four-direction spherical jittering and multi-scale proposal refinement.
- Scale-Rotation Score Consistency (SRC) loss.
- Compatibility with downstream panoramic detectors such as Sph-CenterNet, SSD, FCOS, and Faster R-CNN variants.

### Spherical RoI feature extraction

The spherical RoI extractor constructs a dense grid on the local tangent plane of an RBFoV, back-projects the sampling points to continuous ERP coordinates, selects an appropriate FPN level according to the tangent-plane scale, and aggregates the sampled features into a fixed-size RoI representation.

## Main results

### Pseudo-BFoV generation quality on 360-Indoor

| Method | mAP | AP<sub>50</sub> |
|---|---:|---:|
| **P<sup>2</sup>DNet** | **9.56** | **31.04** |
| P2BNet-BFoV | 5.95 | 20.42 |
| PointOBB-BFoV | 4.37 | 17.11 |

### Detection performance under the same annotation budget

| Training supervision / detector | mAP | AP<sub>50</sub> |
|---|---:|---:|
| Sph-CenterNet with limited manual BFoVs | 6.01 | 14.19 |
| **P<sup>2</sup>DNet + Sph-CenterNet** | **7.33** | **18.51** |
| SSD with limited manual BFoVs | 4.23 | 11.60 |
| P<sup>2</sup>DNet + SSD | 5.85 | 15.10 |
| FCOS with limited manual BFoVs | 2.31 | 6.50 |
| P<sup>2</sup>DNet + FCOS | 4.15 | 9.50 |
| Faster R-CNN with limited manual BFoVs | 5.19 | 13.00 |
| P<sup>2</sup>DNet + Faster R-CNN | 6.61 | 16.42 |

> The values above correspond to the current manuscript and may be updated together with the released checkpoints and final evaluation protocol.

## Installation

### 1. Create the environment

```bash
conda create -n pointobb python=3.7 -y
conda activate pointobb
```

### 2. Install PyTorch

```bash
pip install torch==1.9.0+cu111 \
    torchvision==0.10.0+cu111 \
    torchaudio==0.9.0 \
    -f https://download.pytorch.org/whl/torch_stable.html
```

### 3. Install MMCV

```bash
pip install mmcv-full \
    -f https://download.openmmlab.com/mmcv/dist/cu111/torch1.9.0/index.html
```

Use an `mmcv-full` build compatible with the installed PyTorch, CUDA, and MMDetection versions. Do not mix incompatible MMCV 1.x and 2.x APIs in the same environment.

### 4. Install this repository

```bash
# Run inside the repository root.
pip uninstall -y pycocotools
pip install -r requirements/build.txt
pip install -v -e . --user

chmod +x tools/dist_train.sh
```

### 5. Additional dependencies

```bash
conda install scikit-image
# or:
# pip install scikit-image
```

When formatting-related errors occur, the following version may help:

```bash
pip install yapf==0.40.0
```

## Dataset preparation

The current experiments use the **360-Indoor** panoramic dataset. The dataset is not redistributed in this repository.

After downloading the dataset:

1. Place images and annotations in a local data directory.
2. Update `data_root`, annotation paths, and image prefixes in the corresponding config file.
3. Check that ERP images are loaded with the expected width and height before training.

The main configuration used in the current experiments is:

```text
configs2/COCO/P2BFoV/P2BFoV_r50_fpn_1x_coco_ms.py
```

## Training

### Single-GPU training

```bash
python tools/train.py \
    configs2/COCO/P2BFoV/P2BFoV_r50_fpn_1x_coco_ms.py \
    --work-dir work_dir/P2BFoV/ \
    --gpu-ids 1
```

### Distributed training on two GPUs

```bash
bash tools/dist_train.sh \
    configs2/COCO/P2BFoV/P2BFoV_r50_fpn_1x_coco_ms.py \
    2
```

Specify visible GPUs explicitly:

```bash
CUDA_VISIBLE_DEVICES=0,1 \
bash tools/dist_train.sh \
    configs2/COCO/P2BFoV/P2BFoV_r50_fpn_1x_coco_ms.py \
    2
```

### Distributed training on four GPUs

```bash
CUDA_VISIBLE_DEVICES=0,1,2,3 \
bash tools/dist_train.sh \
    configs2/COCO/P2BFoV/P2BFoV_r50_fpn_1x_coco_ms.py \
    4
```

### Resume training

```bash
CUDA_VISIBLE_DEVICES=0,1 \
bash tools/dist_train.sh \
    configs2/COCO/P2BFoV/P2BFoV_r50_fpn_1x_coco_ms.py \
    2 \
    --work-dir work_dir/P2BFoV/ \
    --resume-from work_dir/P2BFoV/epoch_13.pth
```

## Validation and inference

### Single-GPU validation with the current training entry

```bash
python tools/train.py \
    configs2/COCO/P2BFoV/P2BFoV_r50_fpn_1x_coco_ms.py \
    --work-dir work_dir/P2BFoV/ \
    --gpu-ids 0 \
    --cfg-options \
        load_from=work_dir/P2BFoV/epoch_8.pth \
        runner.max_epochs=0 \
        evaluation.interval=1
```

## Result conversion, visualization, and evaluation

Convert model outputs to COCO-style JSON:

```bash
python bfov/temp_json/bfov2coco/merge_detection_results.py
```

Visualize pseudo-BFoV or detection results:

```bash
python bfov/temp_json/bfov2coco/bfov_batch_visualization.py
```

Evaluate BFoV metrics:

```bash
python bfov/calculate_bfov_metrics.py
```

Before running these scripts, check their input and output paths and make sure they point to the current experiment directory.

## Reproducibility and experiment management

For every experiment, preserve at least the following files:

```text
work_dir/<experiment_name>/
├── config.py
├── train.log
├── inference.log
├── checkpoints/
│   ├── epoch_x.pth
│   └── latest.pth
├── predictions/
│   └── results.json
├── visualizations/
└── metrics/
```

A recommended experiment name contains the date, model variant, and key change, for example:

```text
2026-06-28_head8_spherical_roi
```
